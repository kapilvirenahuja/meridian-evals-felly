nestjs-module

Handles all authentication flows: registration, login (email+password and social), email verification, password reset, token refresh, and logout. Issues JWTs via MockAuthAdapter (DI-swappable for KeyCloakAuthAdapter in E11). Provides JwtAuthGuard and RolesGuard used by all other modules. Enforces INV-02 (single role per user) and INV-04 (unique email) and INV-05 (passwords never in responses).

Key Files:
  • src/auth/auth.module.ts — Provides AUTH_ADAPTER_TOKEN → MockAuthAdapter, PassportModule, JwtStrategy; exports JwtAuthGuard, RolesGuard, Roles decorator, CurrentUser decorator
  • src/auth/auth.controller.ts — REST routes: POST /auth/register, POST /auth/login, POST /auth/logout, POST /auth/refresh, GET /auth/verify-email, POST /auth/forgot-password, POST /auth/reset-password, GET /auth/social/google, GET /auth/social/google/callback, GET /auth/social/apple, POST /auth/social/apple/callback, GET /auth/me
  • src/auth/auth.service.ts — Orchestrates IAuthAdapter calls with User persistence in PostgreSQL. register() → calls adapter.register() + creates User row + creates MenteeProfile/MentorProfile. login() → calls adapter.login(), writes AuditLog.   • src/auth/adapters/auth-adapter.interface.ts — IAuthAdapter interface: register(), login(), socialLogin(), logout(), refresh(), forgotPassword(), resetPassword(), verifyEmail(), validateToken()

6. Design Patterns

Backend Patterns

Each domain module (auth, user, admin) has a dedicated *Repository class that owns all Prisma queries for that domain. Services inject the repository and never call PrismaService directly. Repository methods are named after the operation they perform (findById, listPending, updateStatus) — not after SQL operations.

Service classes own all business logic: invariant enforcement, state machine transitions, completeness calculation, AuditLog writes, and cross-entity consistency. Controllers are thin HTTP adapters — they extract DTOs, call one service method, and return the result via plainToInstance serialization.

Request DTOs use class-validator decorators. Global ValidationPipe (whitelist, transform). Response DTOs use class-transformer @Exclude()/@Expose() to control serialization. @ApiProperty decorators on all DTO fields for OpenAPI spec generation. plainToInstance(ResponseDto, entity, { excludeExtraneousValues: true }) on all controller returns.

HttpExceptionFilter registered globally in main.ts catches all HttpExceptions. Prisma constraint errors (P2002, P2025) mapped to ConflictException and NotFoundException in service methods. All errors return { statusCode, message, error, timestamp } shape.

JwtAuthGuard and RolesGuard always applied as a pair. @Roles() decorator sets required roles on handler metadata. @CurrentUser() decorator extracts JwtPayload from request. @Public() decorator marks routes that skip JWT validation. This pattern is KeyCloak-compatible — same guards and decorators work when MockAuthAdapter is swapped for KeyCloakAuthAdapter in E11.

Each module's @Module({ exports: [...] }) declares only what other modules may use. No module imports another module's internal service unless it is exported. PrismaModule is @Global() and exports PrismaService (exception to avoid repeated imports). AuthModule exports guards and decorators only — not AuthService.

Any service method that writes to multiple Prisma models within one logical operation uses this.prisma.$transaction([...]) or the interactive transactions API. Examples: createMentorWithUser() (creates User + MentorProfile atomically), approveMentor() (updates MentorProfile + User status + AuditLog atomically).

Frontend Patterns

(auth) route group: unauthenticated pages with auth layout (no nav). (app) / (portal) route group: authenticated pages with full nav layout. Route group name is NOT part of the URL path — (auth)/login renders at /login. Each group has its own layout.tsx defining the shared UI wrapper.

Page components (page.tsx) are server components unless they need interactivity. Form components, hooks, and anything using useState/useEffect are 'use client'. The QueryProvider wrapper is 'use client' wrapping server layouts. This minimises client bundle size and maximises SSR for public pages.

All API data fetching uses TanStack Query hooks (useQuery for reads, useMutation for writes). Hook files in src/hooks/ encapsulate query keys, fetcher functions, and mutation callbacks. No direct axios calls in page/component files. On successful mutations (profile update, approve/reject), invalidate relevant query keys. 

// hooks/useProfile.ts
export const useProfile = () => useQuery({
  queryKey: ['mentee-profile'],
  queryFn: () => apiClient.get<IMenteeProfile>('/users/me/mentee-profile').then(r => r.data),
});
export const useUpdateProfile = () => useMutation({
  mutationFn: (data: Partial<IMenteeProfile>) =>
    apiClient.patch('/users/me/mentee-profile', data).then(r => r.data),
  onSuccess: () => queryClient.invalidateQueries({ queryKey: ['mentee-profile'] }),
});

Forms use react-hook-form with useForm<z.infer<typeof schema>>() and zodResolver. Zod schemas defined alongside form components — field-level validation messages match the API's validation error messages. Form submission calls TanStack Query useMutation — no direct axios in form onSubmit handlers. 

const loginSchema = z.object({
  email: z.string().email('Enter a valid email'),
  password: z.string().min(1, 'Password is required'),
});
const { register, handleSubmit, formState: { errors } } = useForm<z.infer<typeof loginSchema>>({
  resolver: zodResolver(loginSchema),
});

Single Axios instance configured with base URL from NEXT_PUBLIC_API_BASE_URL. Request interceptor adds Bearer token from localStorage. Response interceptor handles 401: calls POST /auth/refresh, updates tokens, retries original request once. If refresh fails: clears tokens, redirects to /login.

Components installed via shadcn CLI (npx shadcn add button input card dialog, etc.) into src/components/ui/. These are source files — edit directly if customization needed. cn() utility function (clsx + tailwind-merge) used for conditional classes. All form inputs use shadcn Input and Label for consistent styling and accessibility.
